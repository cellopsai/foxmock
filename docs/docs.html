FoxMock Documentation

FoxMock is a free IntelliJ IDEA plugin that runs real REST, gRPC, SFTP and SMTP mock servers inside your IDE. No external processes, no configuration files, no containers. Install the plugin, define your mocks, and start developing immediately.

Installation

  1. Open IntelliJ IDEA
  2. Go to File → Settings → Plugins (macOS: IntelliJ IDEA → Settings → Plugins)
  3. Open the Marketplace tab and search for FoxMock
  4. Click Install, then restart the IDE when prompted

After restarting, click the FoxMock tab in the bottom tool window, or open it via View → Tool Windows → FoxMock.

Tip: FoxMock is also available directly from the JetBrains Marketplace via the Install widget below.

Overview

The FoxMock tool window has four protocol tabs:

  • HTTP — REST route mocking on a configurable port (default 8080)
  • gRPC — Protocol Buffer service mocking on a configurable port (default 9090)
  • SFTP — File-transfer server simulation with configurable file listings and responses
  • SMTP — Outbound email capture — no real emails sent, full inspection in the transaction log

All tabs share the same concepts: routes/methods have multiple scenarios (named response configurations), and requests are matched using a three-tier resolution system.

Three-Tier Scenario Resolution

Every incoming request goes through this logic:

  1. Conditional scenarios — Evaluated in priority order. The first scenario whose conditions all match wins.
  2. Manually active scenario (●) — If no conditional scenario matched, the scenario you last set as active is served.
  3. First enabled scenario — Safety net: if the active scenario is disabled, the first enabled one is used.

REST — Creating Routes

In the HTTP tab, click Add Route and fill in:

  • Method — GET, POST, PUT, DELETE, PATCH, or ANY
  • Path — the URL path, e.g. /api/users/{id}. Path variables like {id} are captured and available in conditions.

You can load multiple routes from a collection file using Load Collection.

REST — Configuring Responses

Double-click a route (or right-click → Configure…) to open the scenario editor. The editor has:

Response Tab

  • Status — HTTP status code (200, 404, 500, etc.)
  • Headers — Response headers as key-value pairs
  • Body — JSON or any text response body
  • Delay — Artificial latency in milliseconds

Auto-generating the body

Click ⚙ Generate from Schema to auto-fill the body from an OpenAPI or JSON schema definition. Click 🤖 Generate with AI to stream a realistic payload from your configured AI provider.

REST — Scenarios

Each route can have multiple named scenarios. The scenario editor (opened by double-clicking a route) shows all scenarios in the left panel. The active one is marked ●.

Adding a scenario

  1. Click Add in the scenario list
  2. Type a name and press Enter
  3. Fill in the response fields and click Save

Switching the active scenario

Select a scenario and click Set Active. The ● badge moves instantly. You can also right-click a route row → Switch Scenario without opening the editor.

Note: The active scenario is the fallback when no conditional scenario matches. Make sure your "happy path" scenario is set active by default.

gRPC — Loading a .proto File

In the gRPC tab, FoxMock needs the .proto file to discover your service structure.

Drag-and-drop the .proto file onto the Proto Files table, or click Load Proto File and browse to it.

After loading you will see:

  • Proto Files table — one row per loaded file, with service count, method count, and status
  • Methods table — one row per RPC method, pre-filled with a generated sample JSON response

You can load multiple .proto files if your services are spread across several files.

Note: FoxMock parses proto3. If your proto imports other files, those files must be on disk in a path relative to the loaded file.

gRPC — Starting the Server

Click Start Server. The status label changes to Status: Running — port 9090.

The default port is 9090. Change it any time in Settings → Tools → FoxMock → gRPC Port — the server restarts automatically.

The server is plaintext (no TLS). Point your client at localhost:9090 using the insecure/plaintext channel variant.

gRPC — Configuring Methods

Double-click any row in the Methods table (or right-click → Configure…) to open the scenario editor.

Response Tab

  • Status — gRPC status code: OK, NOT_FOUND, INTERNAL, etc.
  • Message — optional text sent alongside a non-OK status
  • Delay — artificial latency in milliseconds
  • Response body — the JSON body (JSON-transcoded from the proto message)

Click ⚙ Generate from Proto to regenerate a sample from the proto message definition. Click Save when done.

gRPC — Scenarios

gRPC methods support the same multi-scenario system as REST routes. A typical set for a user lookup:

  • success — status OK, full user object
  • not_found — status NOT_FOUND, empty body, message "User does not exist"
  • server_error — status INTERNAL
  • slow_response — status OK, full user object, delay 3000 ms

Scenario badges in the list:

  • ● bold — the active fallback scenario
  • ⚡ — has at least one condition
  • ⚡● — conditional AND is the active fallback
  • Gray / italic — disabled (never served)

gRPC — Connecting Your App

The server listens on localhost:9090 by default. Use the insecure/plaintext channel variant of your client:

ManagedChannel channel = ManagedChannelBuilder
    .forAddress("localhost", 9090)
    .usePlaintext()
    .build();
conn, _ := grpc.Dial("localhost:9090", grpc.WithInsecure())
channel = grpc.insecure_channel("localhost:9090")
const client = new UserServiceClient(
  "localhost:9090",
  grpc.credentials.createInsecure()
);

SFTP — Overview

The SFTP tab starts a mock SSH File Transfer Protocol server inside IntelliJ. Your app connects to it exactly like a real SFTP server — no SSH key setup, no real host required.

Use it to test file-upload flows, download handlers, or directory listing logic without a remote server or VPN.

Note: The mock SFTP server accepts any username and password by default. Authentication credentials can be configured in Settings → Tools → FoxMock → SFTP.

SFTP — Configuring Responses

Open the SFTP tab and click Start Server. Configure responses for each operation type:

  • List — define the files and directories returned for a given path
  • Download — set the file content returned when your app reads a file
  • Upload — configure the success/failure response when your app writes a file
  • Stat — set file metadata (size, permissions, modified time) returned for a path

Each operation supports multiple scenarios — return a normal listing for one path, a permission-denied error for another.

SFTP — Connecting Your App

The server listens on localhost:2222 by default (configurable in Settings). Point your SFTP client at that host and port:

Host:     localhost
Port:     2222
User:     any
Password: any

Java (JSch), Python (paramiko), Node.js (ssh2), and any other standard SFTP client will connect without modification beyond the host and port.

SMTP — Overview

The SMTP tab starts a mock mail server. Any email your app sends to localhost:2525 is captured and displayed in the transaction log — nothing is ever forwarded to a real mail relay.

Use it to test welcome emails, password-reset flows, notification triggers, and any other email-sending code without a real SMTP provider or a tool like MailHog running separately.

Tip: The mock SMTP server accepts all recipients and all sender addresses. No DNS, no SPF, no TLS required.

SMTP — Inspecting Captured Mail

Every message received is logged in the Transaction Log pane of the SMTP tab. Each entry shows:

  • From / To — sender and recipient addresses
  • Subject — message subject line
  • Headers — full MIME headers
  • Body — plain-text and HTML parts, expandable inline
  • Timestamp — when the message was received by the mock server

Point your app at localhost:2525 (or your configured port) with no credentials and no TLS. The mock server accepts the connection and captures everything.

Host:     localhost
Port:     2525
TLS:      none
Auth:     none

What Are Scenarios

A scenario is a named response configuration for a single route or gRPC method. Having several scenarios per route lets you switch what the mock returns with a single click — no code changes, no restarts.

Each scenario has:

  • A name (e.g. success, not_found)
  • An enabled flag — disabled scenarios are skipped entirely
  • A response (status, headers/message, body, delay)
  • Optional match conditions (for automatic switching)
  • A priority (for ordering conditional scenarios)

Switching Scenarios

In the configure dialog: Select a scenario and click Set Active. The ● badge moves to that scenario immediately.

From the route/method table: Right-click a row → Switch Scenario → choose from the submenu. No dialog needed.

Disabling Scenarios

To temporarily remove a scenario without deleting it:

  1. Open the Configure dialog
  2. Select the scenario
  3. Uncheck Enabled
  4. Click Save

The scenario turns gray and italic. FoxMock skips it completely — conditions are not evaluated and it is never used as a fallback. Re-enable it by ticking the checkbox again.

Conditional Matching

Conditional matching lets the mock automatically serve different scenarios based on request content — without manual switching. This is ideal for automated tests that need deterministic responses.

How to add a condition

  1. Open the Configure dialog for a route or gRPC method
  2. Select (or add) a scenario
  3. Click the Conditions tab
  4. Click Add Condition
  5. Set Type, Path/Key, Operator, and Value
  6. Click Save

The scenario will now show a ⚡ badge. FoxMock evaluates it automatically on every request.

Condition Types

TypeDescriptionExample path
Body JSONPath Extracts a value from the request body using a JSONPath expression $.user.role
Body Regex Tests the whole request body against a regular expression .*admin.*
Body Exact The entire request body must equal the given string {"id":"1"}
Query Param Matches a URL query parameter by name (HTTP only) userId
Header Matches a request header by name (HTTP only) X-Tenant-ID
Note: gRPC conditions support Body types only, since gRPC requests are transcoded to JSON and only the body is available for matching.

Operators

OperatorBehaviour
EqualsExtracted value must exactly match the given value
ContainsExtracted value must contain the given string as a substring
Matches (regex)Extracted value must fully match the given regular expression
ExistsThe path or key must be present in the request (value is ignored)

All conditions on a single scenario use AND logic — every condition must pass for the scenario to win.

Priority

When multiple conditional scenarios could match the same request, the one with the lowest Priority number wins (0 = highest priority). Set the priority in the Conditions tab via the Priority spinner.

Two scenarios with the same priority that both match will resolve non-deterministically — assign different priorities when your conditions overlap.

AI Response Generation

If your messages have many fields, typing realistic JSON by hand is tedious. FoxMock has two generation options in the Response tab:

⚙ Generate from Proto / Schema

FoxMock reads the proto message definition (or OpenAPI schema for HTTP) and produces a sample with realistic-looking values: email fields get an email address, id fields get a UUID-style string, price fields get a decimal.

🤖 Generate with AI

If you have configured an AI provider in Settings → Tools → FoxMock → AI Provider, this button sends the field definitions to the AI and streams the result into the editor.

Supported providers:

  • OpenAI — requires an API key
  • Claude (Anthropic) — requires an API key
  • Ollama — local model, no key needed
  • Local CLI — any command-line tool that reads a prompt and writes JSON to stdout
Tip: The AI console window streams output in real time. A timer shows how long generation has been running. You can cancel at any time.

Save & Load Collections

Your mock configuration (routes/methods, scenarios, conditions, priorities) can be saved to a file and restored at any time.

Save

Click Save Config (HTTP) or Save Config (gRPC). Choose a filename. FoxMock writes a JSON file:

  • HTTP: .foxmock extension
  • gRPC: .foxmock-grpc extension

Load

  1. For gRPC: load your .proto file first
  2. Click Load Config
  3. Select the .foxmock or .foxmock-grpc file

All scenarios are restored. Methods not found in the loaded proto are skipped and listed in the confirmation dialog.

Tip: Commit the .foxmock-grpc file alongside your .proto files in version control. Your whole team can load the same mock setup in two clicks.

File format

{
  "name": "gRPC Config",
  "version": "1.0",
  "services": [{
    "serviceName": "com.example.UserService",
    "methods": [{
      "methodName": "GetUser",
      "activeScenario": "success",
      "scenarios": [
        {
          "name": "success",
          "enabled": true,
          "statusCode": "OK",
          "delayMs": 0,
          "responseJson": "{ \"id\": \"user-123\", \"name\": \"Alice\" }",
          "matchConditions": [],
          "priority": 0
        }
      ]
    }]
  }]
}

Transaction Log

Every call is logged in the Transaction Log pane at the bottom of the panel. Each entry shows:

  • Method / path (HTTP) or service and method name (gRPC)
  • Duration in milliseconds
  • Status code returned
  • Which scenario was matched

Use it to confirm your app is hitting the mock and to see exactly which scenario resolved for a given request.

Troubleshooting

Connection refused

Confirm the port in FoxMock matches your client's target port (Settings → Tools → FoxMock → HTTP Port / gRPC Port) and that the status label says Running.

UNIMPLEMENTED (gRPC)

The method your client is calling is not in any loaded .proto file. Load the correct proto and ensure the service and method names match exactly.

Wrong response

Make sure you clicked Save after editing. Check the Transaction Log to see which scenario was actually resolved. Make sure the scenario you expect is active (● badge) or that its conditions matched.

Proto fails to load

FoxMock parses proto3. If your proto imports other files, those files must be on disk in a path relative to the loaded file.

AI generation times out

The CLI console shows an elapsed-time counter. If the AI is slow, wait — some models take 30–60 seconds for large schemas. You can cancel and try a smaller model or Ollama locally.

FAQ

Is FoxMock free?

Yes — free during the beta period, with all features included. No credit card required.

Does it support gRPC streaming?

Unary calls are fully supported. Streaming support (server-streaming, client-streaming, bidirectional) is on the roadmap.

Can I use FoxMock in CI/CD?

FoxMock runs inside the IDE, so it's best suited for local development. For CI use cases, consider exporting your config and integrating a headless mock server. A standalone mode is planned.

Does FoxMock support TLS?

Not currently. The mock server uses plaintext HTTP/2 for gRPC and HTTP/1.1 for REST. Configure your test client to use the insecure/plaintext channel.

Can the whole team share the same mock config?

Yes. Save your config as a .foxmock or .foxmock-grpc file and commit it to version control. Each team member loads it with Load Config.
